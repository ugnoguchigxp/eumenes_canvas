# P2 結果（記録済み推論による代行評価）

2026-11-09 実施。Chromium 141.0.7390.37（Playwright 1.56.1、headless）、Bun 1.4.4。条件の凍結は [p2-eval.md](p2-eval.md)。

## 最初に読むこと（正直な表示）

- **Luna／Haiku は使っていない。** 利用者のローカルモデルのため、Grok Bot が制作担当を代行し、その出力を記録済み推論として製品と同じ経路で再生した。製品コードにモデル名は無い（`ModelPort`・`RecordedProvider`）。
- **生成と判定は同じ Grok Bot**（盲検でない）。判定コードは制作の前に凍結した（commit `0edd712`）。制作の記録は凍結の後の `df1aff9`。
- **3 回の試行は独立したセッションではない。** 同じ作業の中で書き分けた 3 案（sample 0〜2）。
- 遅延は記録の再生（契約検査・ブラウザ観測・保存）だけ。**実モデルの推論時間・費用は未測定。**
- 下記の合格率は Luna／Haiku の性能を示さない。§4 の「作れる・直せる」「待てる時間」は、実モデルでは**未測定**。

### 不合格の原因

- **N1 の sample 0・1（制作側の不具合）。** Space を押すと上向きの速度を設定するが、ホストが入力の直後に `frame(0)` を呼ぶと、着地判定（高さ ≤ 0 なら速度 0）が同じフレームで速度を消してしまい、跳ばない。ホストの汎用観測は「入力で描画が変わる」しか見ないので通過した。依頼どおりの操作を自動で確かめないと、このような不具合を候補として提示してしまう。sample 2 は経過時間で高さを計算する方式で、影響を受けない。
- **N3 の全 3 案（判定側の不具合）。** 凍結した判定は敵の横速度を 16ms の 1 フレームの差から推定する。描画の丸めで 0.1 px/ms が 0.125 と測られ、照準が約 16px ずれて命中しなかった。作品が依頼どおり動くことは個別の観測で確かめた（弾が 0.4 px/ms で上がり、敵は 0.1 px/ms で往復）。

## 評価版 v2（参考。正式な数には混ぜない）

N3 の判定だけを直した版（速度を 160ms 以上の区間で推定する）。対照（空の作品は不合格）は期待どおり。同じ記録で N3 は **3/3**。v2 を当てはめると新規 10/12・ゲーム計 34/36 となり、群と合計の基準は満たすが、N1 は 1/3 のまま課題ごとの基準は未達。v2 は結果を見た後に直した判定なので、N3 はこれ以後「未使用課題」として扱えない。

## 実モデルで行うために必要なこと

1. Luna／Haiku を呼ぶ `ModelPort` の実装（利用者のローカル環境の接続先・認証・設定）。この環境からは呼べない。
2. 同じ課題を、モデルごとに 3 回、新しいセッションで実行（13 課題×3 回×2 モデル）。v1 の課題のうち N3 は調整に使ったので外すか、新しい課題で置き換える。
3. 生成と独立した判定者による照合と、判定が割れたときの人による裁定。
