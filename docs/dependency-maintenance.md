# 依存と配布物の保守

## 依存の範囲

直接依存の版は [package.json](../package.json)、実際の解決結果と整合性情報は [bun.lock](../bun.lock) に記録する。配布候補は同じ解決情報から、配布用マニフェストに対応したロックファイルを生成する。Bun の版は `packageManager`、観測に使うブラウザの版は Playwright が指定する。 [Playwright のブラウザ管理](https://playwright.dev/docs/browsers)

| 実行箇所 | 依存（2026年11月12日時点） | パッケージのライセンス表示 |
| --- | --- | --- |
| 候補の検査・配信 | TypeScript 5.9.3 | Apache-2.0 |
| Chromium の観測とブラウザ試験 | @playwright/test、playwright、playwright-core 1.65.0 | Apache-2.0 |
| 画素の読み取り | pngjs 7.0.0 | MIT |
| 宣言した作品のブラウザに配信 | three 0.187.0、cannon-es 0.20.0 | MIT |

型検査用の依存はリポジトリのロックに含まれる。配布用マニフェストからは型検査用の直接依存を外す。表はパッケージが掲示する分類で、ブラウザ本体、配信時に束ねたコード、プロジェクト本体はそれぞれ配布形態に応じて表示と条件を確認する。外部配布の範囲と責任は本体の配布判断で記録する。

固定インストールした配布候補では、上の7パッケージすべてに `LICENSE` または `LICENSE.txt` があり、Playwrightの3パッケージには `NOTICE` もある。2026年11月12日に照合した公開リポジトリのGitHubライセンス欄は未設定だった。候補に収録されたプロジェクト自身の組み込み・利用条件は確認できていない。

Three.js と cannon-es をブラウザへ配信するときは、インストールした固定版の `LICENSE` を配信コードに添える。Worker とページ直接モードのスクリプトを組み立て、パッケージの通知が含まれることを回帰試験で確認する。 [配信コードの組み立て](../src/server/preview.ts#L101) · [通知の回帰試験](../tests/unit/render-libraries.test.ts)

配布アーカイブの記録時刻を固定し、完成したアーカイブのSHA-256をファイル名と照合用のファイルに反映する。Bunが生成するUSTARの通常ファイルだけを対象に、時刻とヘッダーのチェックサムを揃える。 [USTARのヘッダー形式](https://www.gnu.org/software/tar/manual/html_node/Standard.html)

## 独立版のデータを守って更新する

1. 現在使っている設定、コードの版、`dataDir` を控える。設定ファイルに相対パスを書いた場合、`dataDir` はリポジトリのルートを基準にする。`dataDir: null` の場合はメモリだけに保存するため、この手順で退避するファイルはない。
2. 生成・保存・復元が終わったことを画面で確認し、検証ホストを止める。同じ `dataDir` を使うデモ投入も終わらせる。退避先は `dataDir` の外に用意し、作品データと元の版を保持する。設定を退避する際は、キーを入れた環境ファイルはそのまま管理する。
3. 新しい版の別の作業コピーで固定インストールと `bun run verify` を行う。新しい設定に専用の `dataDir` と空いている2ポートを指定し、退避した `store.json` のコピーを入れる。一覧、現在版、履歴から選んだ版の再表示、別の版への復元を確認してから、新しい版を通常の `dataDir` で起動する。
4. 起動や確認に失敗したら新しい版を停止し、失敗時点の `store.json` があれば別の場所に保存する。退避したファイルを元の `dataDir` に戻し、元の版と設定で起動する。新しい版で退避後に確定した更新は、退避版には含まれない。一覧の件数、対象作品の現在版と履歴、プレビューを再確認する。

ホストを端末から起動している場合は `Ctrl+C`、別プロセスから停止する場合は `SIGTERM` で終了する。待ち受けを止めてから制作を中断し、観測用ブラウザを閉じる。終了処理が5秒で終わらない場合はエラーとして終了する。保存した版は再起動後に開ける。停止時に実行中だった制作は中断と表示する。

以下は、ホストとデモ投入を止めてから使う macOS の操作例。`data_dir` と `backup_dir` は実際の絶対パスに置き換える。

```sh
data_dir="$PWD/.data"
backup_dir="$(mktemp -d "$HOME/canvas-backup.XXXXXX")"
cp -p "$data_dir/store.json" "$backup_dir/store.json" &&
  cmp "$data_dir/store.json" "$backup_dir/store.json"
```

復旧時は退避に使った同じ `backup_dir` を指定する。コピーを照合してから、同じディレクトリ内の名前変更で現在のファイルを置き換える。

```sh
restore_tmp="$(mktemp "$data_dir/.restore.XXXXXX")" &&
  cp "$backup_dir/store.json" "$restore_tmp" &&
  cmp "$backup_dir/store.json" "$restore_tmp" &&
  mv -f "$restore_tmp" "$data_dir/store.json"
```

## 更新時と取込候補の確認

1. `bun install --frozen-lockfile` でマニフェストとロックの整合を確かめる。`bun audit --json` の結果に実行日と対象ロックを付けて記録する。照合できなかった依存や接続失敗は未確認として扱う。
2. 通知がある場合は、対象の版と用途、到達する実行経路を確認し、更新、利用範囲の制限、例外の見直し時期を判断する。npm の依存の照合に加え、採用する Bun、Chromium、WebKit のリリースと安全性の情報を確認する。
3. Playwright を更新するときは、既存のブラウザ版を使った過去の評価記録を保ち、更新候補のブラウザで隔離・停止、画素判定、操作・保存を測る。固定試験の差が出た場合は、実装・ブラウザ・判定器のどこに差があるかを記録する。
4. `bun run release:prepare` で取込候補を作る。作業中のソースを一時ディレクトリにコピーし、ロックファイルどおりにインストールする。同じコピーで全体試験、評価器の型検査、配布物の再現・展開試験を行い、合格した候補を `eval/out/dist/` に出力する。依存がローカルにそろっている場合は `--offline` を指定できる。出力先を変更するときはディレクトリを引数に渡す。
5. 作成済みの候補は `.tgz` を `bun run verify:package` に渡して照合する。アーカイブと同梱ファイルのハッシュ、公開契約、固定インストール、旧保存版の再表示と復元を検査する。展開先のコアで固定作品を観測し、受領結果を再取得しても版が増えないことと、Workerが停止することも確かめる。

## 現行版の観測

2026年11月12日、Bun 1.4.4で、更新前のロックのnpm公開パッケージ13件と更新後の12件を `bun audit --json` で照合した。いずれも終了コード0、応答は空の報告（`{}`）。ブラウザ実行ファイル自体はnpm依存の照合の範囲外。 [Bun の照合範囲](https://bun.com/docs/pm/cli/audit)

同日、macOS arm64で Playwright 1.65.0（Chromium 158.0.8127.18、WebKit 27.2）への更新候補を検証した。観測用Chromiumのサンドボックスを有効にし、型検査、部分・結合267件、ブラウザ173件が合格した。ブラウザ条件によるスキップは23件。WebKit 27.2で変わった隔離試験の期待値は[実行境界](../design.md#4-プレビューの実行境界)に記録した。Linuxでの観測用Chromiumのサンドボックス有効化は、環境条件の検証が残る。 [Playwright 1.65.0](https://github.com/microsoft/playwright/releases/tag/v1.65.0)
