## 3. 結果の分解（事実）

### 3.1 3 条件に共通の失敗

- **N1 ジャンプ（D 0/3、C 0/3、P 1/3）**
  - 失敗の内容：Space を押しても自機が上がらない（`jump-space y0=y1=y2=309.5`）。その結果、得点も取れない。
  - 原因：ホストは入力のたびに `frame(t, 0)` を呼ぶ（`src/preview/bootstrap.js:166`）。dt=0 のまま物理を進めると、高さ +0 になり「高さ ≤0 なら着地」で即座に着地する。
  - 合格した P-r1 だけが、dt>0 のときだけ物理を進めていた。
  - 変種試験で確かめた：
    - P-r3 の作品で、入力処理を P-r1 と同じにしても不合格；
    - 最初の障害物を遅らせても不合格；
    - P-r1 の作品は再判定でも合格。
  - 判定器は正しい（製品でも Space で跳べない作品）。
  - **公開契約には dt=0 で呼ばれることが書かれていない**。これが契約の不備。host-smoke は障害物が動くだけで通すため、N1 型（観測は通り判定で落ちる）になる。
  - P-r1 の合格が Pursuit の効果かは判断できない。P-r2・P-r3 は同じ誤りをしているので、偶然の可能性が高い（推定）。
- **N3 シューター（v1 では全条件 0/3）**
  - P2 と同じく、v1 の判定器の誤り。v2 では D 3/3、C 2/3、P 3/3。
  - C-r3 は v2 でも不合格。
- **P-r3 N3**：判定中に screenshot がタイムアウトする例外が出た（基盤の問題）。v1 では別の理由でも不合格になる。

## 5. 契約と接続の不備（事実。直すべき順）

1. **実行契約**：入力のたびに `frame(t, 0)` が呼ばれることが書かれていない。N1 の失敗 7/8 の原因。
2. **host-smoke の responds**：固定格子のクリックだけで判定するため、正しい作品を落とす。V1 で偽陰性 10 件。
   - 落ちたときの理由が 1 行だけ（例 `static: 時間の経過・入力で描画が変わらない`）で、どこをクリックしたかを返さない。応答者は格子の推定（P-r3）か、位置を変えて試す（他の実行）しかなかった。
3. **P-r3 の指摘（契約上のリスク）**：新規 4 作品のゲームオーバー画面は、依頼どおり #400000 の単色。観測中にゲームオーバーになると、not-blank・responds に落ちる。依頼仕様と観測器が衝突しうる。今回の実行では起きていない（P-r3：書き込み 16 回中、不合格 2 回。N1 と V1 の 1 回目）。
4. **「10px 間隔」の曖昧さ**：ピッチか隙間か。C-r3 N4 は隙間と解釈した。判定はピッチを前提にしている。
5. **C の返答の制約**：OUTPUT_SCHEMA にあるのは text の 300 字（maxLength）だけで、「2 文」の制約は書かれていない（system を確認）。
6. **C の TOOL_RESULT**：detail が観測の 1 行だけ。D の「ホスト観測」も同じ観測器の文で、受け取る情報の量は同程度（推定）。
7. **P の予算の表示**：policy の attempts 12 と、提出の上限 3 回が別々に表示され、検証担当が誤解した。
8. **判定基盤**：screenshot のタイムアウトが 2 件（C-r2 R1、P-r3 N3）。判定の再実行の規則が無い。

## 6. plan.md の基準でどの条件を採るか

**推奨：どの条件も採らない。** 経路は D（直接生成）のままにし、上の 1〜2（契約と観測器）を直してから測り直す。

根拠（事実）：
- §4「作れる・直せる」を満たす条件が無い。どの条件も新規群 10/12・ゲーム計 32/36・課題ごと 2/3 のいずれかで未達。N3 を v2 にした参考値でも、N1 は 0〜1/3。
- §4 の「Pursuit や Claude Code を初期の本体経路に加える場合は、対象課題で改善した観測と、採用した構成での上記合格記録を残す」も満たさない：
  - P は D より +1（N1 の 1 件。偶然の可能性が高い）で、合格記録の基準に届かない。
  - そのために推論は 3.6 倍、推定トークンは 6.9 倍、ホスト側時間は約 3 倍かかる。
- C は D より −2：1 件は基盤の例外、1 件は観測器の偽陰性と確認返答。推定トークンは 1.7 倍。改善の観測は無い。
- 失敗の主な原因（dt=0 の契約の不備、N3 の判定器、観測器の偽陰性）は、どの条件でも共通。協調の仕方を変えても解けない（事実＋推定）。

不確かさ：
- 1 課題 3 反復なので、条件間の 1〜3 件の差は誤差の範囲（推定）。
- 応答者は Grok Bot の代行で、Luna・Haiku の性能や遅延は表していない（仮定の限界）。
- 課題の大半が 1 回目で通るやさしさのため、Pursuit・Collaborator の仕組みが働く場面がほとんど無かった。難しい課題では差が出る可能性がある（未測定）。
