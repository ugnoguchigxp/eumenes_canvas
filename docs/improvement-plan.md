# eumenes_canvas 改善計画書

2026年11月12日。対象は独立検証版 `0.1.0`（`9236612` と評価開始時の作業差分）。初期の取込対象は Canvas 2D の制作・部分修正・修復と、合成データを使った可視化。[実装計画の受入条件](../plan.md#4-本体へ取り込む条件)と[本体での検証手順](../plan.md#5-eumenes-取込後の検証)を適用する。

技術品質は暫定 **57.7 / 100**（配点カバー率94.7%）。将来性は採点済み項目の参考平均 **53.8 / 100**（同76.7%）で、対象利用者の課題を直接確認できていないため総合点は保留。評価時の型検査、部分・結合243件、Chromium・WebKitのブラウザ試験173件は成功し、ブラウザ条件によるスキップは23件だった。追加確認で、保存・復元の競合、書き込み失敗後の誤った成功、ページ直接モードのログの伏字漏れ、配布物の依存記録の不足を確認した。

継続改善の目標は、**技術品質の正式点85 / 100以上**。前回と同じ評価基準・配点・対象範囲を使い、適用項目の根拠を揃える。各段階では、修正後の挙動、未確認の項目、次に測る対象を記録する。将来性と本体への取込は、それぞれの条件で判断する。

## 2. 最優先の修正

[保存・復元の設計書](save-restore-design.md)で、01・02の確定順序、障害時の挙動、検証手順を定める。

### 01. 保存・復元・取消を確定時に照合する

**確認済み・High。** 同じ現在版を基準に出した復元2件が両方成功した。保存中に取消が確定した候補も保存された。同一受領キーの同時保存は、片方だけが成功し、もう片方は409だった。追加確認は既存の試験支援を使い、サービスを直接呼んで行った。 [保存・復元の実装](../src/core/service.ts#L404) · [既存のサービス試験](../tests/unit/service.test.ts)

- **対応。** 作品本文のハッシュ照合を終えたあと、所有者、実行状態と採用候補、現在版、受領キーを、保存または復元を確定する処理の中で照合する。既存の版・受領記録を使い、両経路で共通の不変条件だけを揃える。
- **完了条件。** 同じ基準版からの異なる操作は一方だけが成功し、取消・撤回が先に確定した候補は保存されない。同じキー・同じ操作の同時要求は同一結果を返し、同じキー・異なる操作は拒否する。保存対保存、保存対復元、復元対復元を試験し、履歴と受領記録が一貫することを確認する。

### 02. 永続化された版だけを保存成功として返す

**確認済み・High。** 作業コピーの試験用保存先で一時ファイルの書き込みを失敗させたあと、障害を除去して同じキーで再試行すると、サービスは保存済みとして成功を返した。保存先を別のストアで読み直すと作品は0件だった。メモリ上の版と受領記録が、ファイル書き込みより先に更新される。 [ストアの更新処理](../src/core/store.ts#L36)

- **対応。** 独立版は既存の単一書き込み元とファイル保存を使い、永続化が成功してから版と受領記録を公開する。書き込み失敗時に、画面と再試行から見える状態を永続化済みの状態と一致させる。本体側は既存の保存・版管理を使い、同じ契約を検証する。
- **完了条件。** 一時ファイルの書き込み・置換の失敗時は旧版が開け、新版の受領記録が見えない。障害除去後に同じキーで再試行し、成功後に再起動して本文・版・受領記録が一致する。応答を受け取れなかった保存を再試行しても版は増えない。保存と復元の両方で確認する。

## 6. 検証と進捗の扱い

- 着手時に対象のコミットと差分、現在の挙動、完了条件を記録する。確認済みの不具合は再現試験で失敗を確かめてから直し、部分→結合→通しで確認する。文書や計測だけの項目は、リンク・条件・原記録を照合して終える。
- 既存の指示・情報・ツール・実行経路を先に確認する。題材や発話に依存する判断はモデルに委ね、個別の再現例は試験へ置く。専用処理が必要なら、共通機構で満たせない条件と観測根拠を記録する。
- 各項目は未着手から始め、作業時に結果のリンク、残作業、阻害要因を追記する。同じ目的で3ラウンド続いたときや、新しい根拠のない失敗が反復したときは、次の変更・再実行の前に、増えた証拠と残作業を見直す。再実行する場合は前回から変わった条件を記録する。
- 完了判定では差分全体を確認する。既存要件と凍結済みの採点を保ち、変更が依頼の特定語句や個別課題に依存していないか、観測結果が改善を裏づけているかを確認する。
